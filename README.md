# Contract AI Analyzer

Русскоязычное веб-приложение для предварительного анализа договоров (DOC, DOCX, PDF с текстовым слоем): извлечение текста, поиск юридических и коммерческих рисков с помощью LLM (OpenRouter или локальный Ollama), серверная проверка цитат (дословное совпадение с текстом договора и отдельная смысловая проверка), отчёты и экспорт в PDF, DOCX, CSV, XLSX.

> Результаты — поддержка работы юриста, а не юридическая консультация. Подтверждённый риск означает, что цитата найдена в тексте и, по оценке модели-верификатора, относится к риску; это не гарантия юридической правильности.

**Статус:** этапы 00–08 выполнены (каркас, роли, загрузка, провайдеры, анализ, UI и экспорт, hardening и e2e). Впереди — дополнительный этап 08A (автоматические зашифрованные бэкапы вне сервера) и финальная приёмка 09. Подробно — [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md).

> **Лицензии.** Для разбора PDF используется PyMuPDF под **AGPL-3.0**. Приложение рассчитано на внутреннее использование в организации; если доступ получат внешние пользователи или приложение будет передаваться третьим лицам, нужна коммерческая лицензия, открытие кода или замена библиотеки — см. [docs/LICENSES.md](docs/LICENSES.md).

## Возможности

- Роли Superadmin / Admin / Analyst / Viewer; доступ к каждому договору проверяется на сервере; владелец выдаёт доступ «просмотр» или «просмотр и анализ».
- Загрузка DOCX, DOC (конвертация в изолированном LibreOffice), PDF с текстовым слоем; номера страниц и пунктов — из документа, а не от модели.
- Анализ по выбранным категориям рисков с учётом стороны договора; межраздельный поиск противоречий и отсутствующих условий; защита от prompt injection; три статуса доказательств: «Подтверждён», «Требует проверки», «Не подтверждён».
- Облачные модели выключены по умолчанию; перед передачей текста внешнему провайдеру — предупреждение и подтверждение пользователя; аварийное отключение облака.
- Журнал аудита (только добавление), отмена и повтор анализа, восстановление после перезапуска.

## Быстрый старт

```bash
cp .env.example .env       # заполните секреты (команды генерации внутри файла) и BOOTSTRAP_ADMIN_*
docker compose up -d --build
curl -s http://127.0.0.1:8080/api/health/ready
```

Откройте http://localhost:8080, войдите как Superadmin из `BOOTSTRAP_ADMIN_*` и смените пароль. Затем: «Модели» → добавьте провайдера (Ollama или OpenRouter) и модель, «Проверить с генерацией», включите модель → «Договоры» → загрузите договор → «Запустить анализ».

## Проверки

```bash
cd backend && ruff check app tests && mypy app tests && pytest        # TEST_DATABASE_URL — для интеграционных тестов
cd frontend && npm run typecheck && npm run lint && npm test && npm run build
```

## Структура

| Каталог | Содержимое |
|---|---|
| `backend/` | FastAPI, SQLAlchemy 2, Alembic, worker (очередь задач в PostgreSQL) |
| `frontend/` | React + TypeScript + Vite + Tailwind, nginx-образ; e2e-сценарии Playwright в `frontend/e2e/` |
| `converter/` | изолированный LibreOffice для DOC |
| `deploy/` | скрипты бэкапа и восстановления |
| `e2e/` | отдельный e2e-стенд: mock-сервер с API Ollama, фикстуры, `run.sh` |
| `docs/` | эксплуатация, безопасность, архитектура, модель угроз, статус, лицензии |
| `CLAUDE.md` | инструкции и контекст для продолжения разработки в Claude Code |
