# Contract AI Analyzer

Русскоязычное веб-приложение для предварительного анализа договоров (DOC, DOCX, PDF с текстовым слоем): извлечение текста со страницами и пунктами, поиск юридических и коммерческих рисков с помощью LLM (облачные OpenRouter и ProxyAPI или локальный Ollama), серверная проверка цитат (дословное совпадение с текстом договора и отдельная смысловая проверка), история анализов, отчёты и экспорт в PDF, DOCX, CSV, XLSX.

> Результаты — поддержка работы юриста, а не юридическая консультация. «Подтверждён» означает, что цитата дословно найдена в тексте договора и, по оценке модели-верификатора, относится к риску; это не гарантия юридической правильности и не гарантия, что найдены все риски.

**Статус (2026-10-29):** выполнены этапы 00–09, 08A, 10 (маскировка конфиденциальных данных перед облачным анализом) и 11 (правила рисков организации), добавлен провайдер ProxyAPI; финальная приёмка — [docs/ACCEPTANCE_CHECKLIST.md](docs/ACCEPTANCE_CHECKLIST.md), результаты проверок — [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md) (раздел «Этап 09»). Приложение готово к **пилотной эксплуатации внутри организации**. Это не заявление о production-готовности: до промышленной эксплуатации нужно выполнить шаги из раздела [«Перед production»](#перед-production).

## Возможности

- Роли Superadmin / Admin / Analyst / Viewer; доступ к каждому договору, анализу и экспорту проверяется на сервере (чужой объект — 404); владелец выдаёт доступ «просмотр» или «просмотр и анализ».
- Загрузка DOCX (текст и таблицы), DOC (конвертация в изолированном LibreOffice без сети), PDF с текстовым слоем; PDF без текстового слоя получает статус «нет текстового слоя» с объяснением (OCR не поддерживается). Проверяются размер, сигнатура, структура контейнера; оригинал хранится отдельно от извлечённого текста.
- Номера страниц и пунктов — из документа (PDF — по самому файлу, DOCX/DOC — по рендеру LibreOffice, приблизительно), а не от модели.
- Анализ по выбранным категориям с учётом стороны договора; межраздельный поиск противоречий и отсутствующих условий (без выдуманных цитат, статус «Требует проверки»); защита от prompt injection; статусы доказательств «Подтверждён», «Требует проверки», «Не подтверждён» (последние скрыты по умолчанию).
- Snapshot модели, провайдера, параметров генерации и версий промптов в каждом анализе; оценка объёма и стоимости до запуска; отмена, повтор, восстановление после перезапуска worker'а.
- Динамический каталог провайдеров и моделей (импорт с сервера провайдера, роли, разрешения пользователей) — без пересборки и перезапуска.
- Облачные модели выключены по умолчанию; перед передачей текста внешнему провайдеру — предупреждение и подтверждение пользователя; аварийное отключение облака.
- Маскировка конфиденциальных данных перед облачным анализом (ФИО, паспортные данные, телефоны, адреса, реквизиты организаций и др.; категории настраивает Superadmin) с обязательным предпросмотром; в отчёте — исходные значения.
- Правила рисков организации: собственные критерии (`RR-001`…), которые модель проверяет вместе со стандартными категориями; найденные по правилу риски помечаются его кодом.
- Журнал аудита (только добавление, защищён триггером БД), без паролей, ключей и текста договоров.
- Экспорт защищён правами доступа; CSV/XLSX защищены от formula injection.
- Бэкап и восстановление; автоматические зашифрованные (age) бэкапы с выгрузкой в S3-совместимое хранилище или каталог и ротацией.

## Архитектура

```
Браузер ──HTTPS (внешний reverse proxy)──▶ frontend (nginx: SPA + прокси /api)
                                              │
                                              ▼
                                   backend (FastAPI)  ◀──── PostgreSQL 17 (данные, сессии, очередь задач, аудит)
                                              │                 ▲
                                   volume storage (оригиналы,   │
                                   текст, экспорт)              │
                                              ▲                 │
                                   worker (извлечение, анализ, экспорт, очистка) ──▶ OpenRouter / ProxyAPI / Ollama
                                              │                                      (SSRF-guard)
                                              ▼
                                   converter (LibreOffice, без сети)
```

| Компонент | Технологии |
|---|---|
| `backend/` | Python 3.13, FastAPI, Pydantic v2, SQLAlchemy 2 (async, psycopg 3), Alembic; очередь задач в PostgreSQL (`FOR UPDATE SKIP LOCKED`) |
| `frontend/` | React 19, TypeScript (strict), Vite, Tailwind 4, React Router 7, TanStack Query, Zod; nginx-образ |
| `converter/` | изолированный LibreOffice: DOC→DOCX, DOCX→PDF (для разметки страниц) |
| `deploy/` | бэкап и восстановление, планировщик, образ инструментов (age, rclone) |
| `e2e/` | отдельный e2e-стенд: mock-сервер с API Ollama, фикстуры, `run.sh` |

Конвейер анализа: структура договора → анализ частей (chunks) → межраздельный проход → дедупликация и шаг A проверки (точное/нормализованное совпадение цитаты с текстом фрагмента, страница и пункт — из метаданных) → повторный запрос ненайденных цитат → шаг B (смысловая проверка моделью-верификатором) → итог. Подробно — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Чистая установка

Требования: Docker Engine/Desktop с Compose v2, ~4 ГБ свободной памяти.

```bash
git clone <адрес репозитория> contract-ai-analyzer && cd contract-ai-analyzer
cp .env.example .env
# Заполните в .env (команды генерации — в начале .env.example):
#   POSTGRES_PASSWORD   python -c "import secrets; print(secrets.token_hex(32))"
#   SECRET_KEY          python -c "import secrets; print(secrets.token_urlsafe(48))"
#   SECRETS_ENCRYPTION_KEYS  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
#   BOOTSTRAP_ADMIN_EMAIL / BOOTSTRAP_ADMIN_PASSWORD / BOOTSTRAP_ADMIN_NAME — первый Superadmin
#   ALLOWED_ORIGINS — точный адрес, с которого открывается приложение
docker compose up -d --build
docker compose ps                                   # все сервисы healthy, migrate — exited (0)
curl -s http://127.0.0.1:8080/api/health/ready      # 200, все checks — ok
```

Миграции применяются автоматически сервисом `migrate` перед стартом backend и worker. Данные хранятся в volumes `pgdata` и `storage` (`docker compose down -v` удаляет их — только с бэкапом).

### Первый Superadmin (bootstrap)

Пароля по умолчанию нет. Superadmin создаётся при первом старте backend только из явно заданных `BOOTSTRAP_ADMIN_*` (пароль — не короче 12 символов и не из списка распространённых). Повторный старт или `docker compose exec backend python -m app.cli bootstrap` ничего не меняет (`skipped_superadmin_exists`) — ни пароль, ни роль.

1. Откройте http://localhost:8080 и войдите с `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` — система потребует сменить пароль.
2. После входа удалите `BOOTSTRAP_ADMIN_*` из `.env`, установите `BOOTSTRAP_ENABLED=false`, выполните `docker compose up -d backend`.
3. Утерян пароль единственного Superadmin: `docker compose exec backend python -m app.cli reset-superadmin-password --email <e-mail>` (временный пароль выводится один раз).

Пользователей создаёт Superadmin/Admin в разделе «Пользователи» (временный пароль, смена при первом входе).

### Настройка OpenRouter

1. Superadmin: «Модели» → «Добавить провайдера» → OpenRouter, адрес `https://openrouter.ai/api/v1`, API-ключ. Ключ шифруется и больше не показывается.
2. «Проверить соединение» (бесплатно) → «Импорт моделей» (контекст и цены из API провайдера; импортированные модели выключены).
3. Карточка модели → «Проверить с генерацией» (короткий платный запрос без данных договоров) → включить модель, выбрать роли и назначение.
4. Включить облачные модели глобально («Модели» → «Облачные модели»). Пользователь при первом выборе облачной модели подтверждает предупреждение о передаче текста провайдеру; при каждом запуске — отдельно отмечает согласие.

### Настройка ProxyAPI

Как OpenRouter, но тип ProxyAPI, адрес `https://api.proxyapi.ru/v1`, ключ — из кабинета proxyapi.ru. ProxyAPI не сообщает в API цены и контекст моделей: после импорта задайте в карточке модели цены (RUB за 1 млн токенов, по каталогу proxyapi.ru) и при необходимости контекстное окно. Подробно — [docs/OPERATIONS.md §11](docs/OPERATIONS.md).

### Настройка Ollama

Модели скачивает администратор: `ollama pull <модель>`.

| Где Ollama | Адрес провайдера | «Разрешить частную сеть» |
|---|---|---|
| В Compose: `docker compose --profile ollama up -d` | `http://ollama:11434` | да |
| На хосте Docker Desktop | `http://host.docker.internal:11434` | да |
| На сервере в локальной сети | `http://10.x.x.x:11434` | да |

Без GPU генерация медленная — задайте таймаут провайдера 300–900 с. Затем: «Проверить соединение» → «Импорт моделей» → «Проверить с генерацией» → включить модель. Подробно — [docs/OPERATIONS.md §11](docs/OPERATIONS.md).

### Работа

«Договоры» → загрузить файл → дождаться «Готов» → «Запустить анализ» (сторона договора, категории, глубина, модель; оценка объёма) → отчёт с фильтрами → экспорт PDF/DOCX/CSV/XLSX.

## Перед production

Что не выполнено или не проверено (подробно — [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md), этап 09, и [docs/SECURITY_AND_PRIVACY.md §13](docs/SECURITY_AND_PRIVACY.md)):

- развёртывание за HTTPS reverse proxy с `APP_ENV=production`, `COOKIE_SECURE=true` на Linux-сервере не проверялось (проверено на Docker Desktop под Windows);
- отдельная роль БД без прав суперпользователя (OPERATIONS §14.7) не внедрена;
- выгрузка бэкапов в реальное облачное S3-хранилище и живой systemd timer не проверялись; планировщик бэкапов нужно установить (`deploy/backup-schedule.sh install`) и задать ключ age;
- общего rate limit на API нет (нужен на reverse proxy при доступе из интернета);
- качество анализа зависит от модели: на `gpt-4o-mini` часть рисков может быть пропущена; выводы требуют проверки юристом;
- при распространении готовых образов — указать авторство и лицензию CC BY-SA 3.0 словарей OpenCorpora из pymorphy3-dicts-ru ([docs/LICENSES.md](docs/LICENSES.md)); исходный код их не содержит.
