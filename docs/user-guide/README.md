# Руководство пользователя: исходники

Здесь лежат исходники [docs/USER_GUIDE.docx](../USER_GUIDE.docx): текст и вёрстка — в `build.cjs`, скриншоты — в `screenshots/`, сценарий съёмки — `shots.cjs`. Сам DOCX хранится в репозитории готовым; эти файлы нужны, чтобы обновлять его вместе с интерфейсом.

| Файл | Назначение |
|---|---|
| `build.cjs` | текст руководства и сборка DOCX (библиотека `docx`, A4, рисунки с подписями) |
| `shots.cjs` | снимает скриншоты с запущенного стенда через Playwright (из `frontend/node_modules`) |
| `screenshots/*.png` | 23 скриншота, которые вставляются в документ; имя файла = имя в `image('…')` в `build.cjs` |
| `package.json` | зависимость `docx@9.5.1` |

## Пересобрать документ без стенда

Если меняется только текст:

```bash
cd docs/user-guide
npm ci
npm run build          # → docs/USER_GUIDE.docx
```

Номер версии приложения и дата редакции заданы на титульном листе в `build.cjs`. Обновляйте их при каждой правке.

## Переснять скриншоты

Нужны запущенный стенд (`docker compose up -d`), учётная запись Superadmin и Playwright (`cd frontend && npm ci && npx playwright install chromium`).

```bash
cd docs/user-guide
CAI_PASSWORD='<пароль Superadmin>' CAI_TEMP_ENABLE_MODELS=1 node shots.cjs
npm run build
```

| Переменная | По умолчанию | Значение |
|---|---|---|
| `CAI_URL` | `http://127.0.0.1:8080` | адрес стенда; должен быть в `ALLOWED_ORIGINS` |
| `CAI_EMAIL` | `root@example.org` | Superadmin, под которым снимаются все разделы |
| `CAI_PASSWORD` | — | обязательно; в файлы не записывается |
| `CAI_TEMP_ENABLE_MODELS` | выключено | `1` — на время съёмки включить все модели, их провайдеров и облачные модели, чтобы снять форму анализа с оценкой объёма и облачным предупреждением. В конце (и при ошибке) состояние каталога возвращается к исходному. Запросов к моделям нет; изменения попадают в журнал аудита и историю конфигурации |

Что берётся со стенда: первый договор с завершённым анализом (карточка, форма анализа, отчёт), договор без текстового слоя, первый пользователь кроме себя, первая локальная модель. Если чего-то нет, снимок пропускается с предупреждением, и в `screenshots/` остаётся прежний файл. Без `CAI_TEMP_ENABLE_MODELS=1` при выключенных моделях пропускаются `new-analysis-estimate` и `new-analysis-cloud`.

> **Конфиденциальность.** На скриншотах видны названия и текст договоров, e-mail пользователей и журнал аудита стенда. Снимайте только на стенде с синтетическими данными (например, договоры из [samples/](../../samples/README.md)), никогда — на рабочем.

Текущие скриншоты сняты 18.10.2026 на локальном стенде с синтетическими данными. На них видны `root@example.org`, тестовые пользователи `acc09-*` и договор `live-contract`. Перед раздачей сотрудникам их лучше переснять на чистом демонстрационном стенде.

## Проверка результата

Рендер в PDF через образ converter (LibreOffice) и просмотр страниц:

```bash
MSYS_NO_PATHCONV=1 docker run --rm --network none -v "$(pwd)/..:/work" --entrypoint soffice \
  contract-ai-analyzer/converter:local --headless --convert-to pdf --outdir /work/user-guide /work/USER_GUIDE.docx
```

В Git Bash на Windows вместо `$(pwd)/..` подставьте путь Windows (`cygpath -w`). PDF-файл в репозиторий не добавляйте.

Тексты кнопок и полей в руководстве берутся из `frontend/src/i18n/ru.ts`, права ролей — из `backend/app/security/policies.py`. При изменении интерфейса сверяйте руководство с этими файлами.
