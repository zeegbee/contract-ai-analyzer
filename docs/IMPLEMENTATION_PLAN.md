# Contract AI Analyzer — план реализации

Этапы соответствуют промптам `01`–`09`. Каждый этап завершается запуском тестов, линтеров и сборки, обновлением `IMPLEMENTATION_STATUS.md` и отдельным Git-коммитом. Следующий этап начинается только после этого.

Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md), угрозы и меры — [THREAT_MODEL.md](THREAT_MODEL.md).

## Предусловия окружения

| Что | Состояние на этапе 01 | Нужно для |
|---|---|---|
| Python 3.13 | есть (3.13.2) | 02+ |
| Node.js 22 | есть (v22.14.0) | 02+ |
| Docker Desktop daemon | установлен (29.8.2), **не запущен** | интеграционные тесты с PostgreSQL, сборка образов, compose smoke test, converter (DOC) |
| PostgreSQL | только через Docker | 02+ |
| LibreOffice | на хосте нет; будет в контейнере `converter` | 04 (DOC) |
| Ollama | на хосте не отвечает на `:11434` | 05 — live-проверка (иначе только mocks) |
| Ключ OpenRouter | не предоставлен | 05 — live-проверка (иначе только mocks) |

Без запущенного Docker интеграционные тесты с БД и проверка DOC-конвертации будут пропущены с явной пометкой.

## Этап 02 — Каркас, БД, Docker

Результат:
- `backend/`: pyproject (FastAPI, SQLAlchemy 2 async + psycopg 3, Alembic, pydantic-settings, structlog), app factory, конфигурация с проверкой обязательных параметров, единый формат ошибок, request ID middleware, security headers, логирование с редактированием, `/api/health/live|ready`.
- ORM-модели и первая миграция для всех сущностей из ARCHITECTURE §5 (схема целиком сразу, чтобы последующие этапы не требовали разрушительных миграций).
- Очередь задач (`Job`) — базовые claim/heartbeat/reaper + каркас worker'а.
- `frontend/`: Vite + React + TS strict + Tailwind + Router + TanStack Query, страница состояния системы на реальном readiness API (без фиктивных данных), oxlint, Vitest.
- `converter/`: Dockerfile и минимальный HTTP-сервис (реальная логика — этап 04).
- `compose.yaml` (db, migrate, backend, worker, converter, frontend, profile `ollama`), сети и volumes, healthchecks, non-root; `.env.example`, `.dockerignore`, `.gitattributes` (LF для `*.sh`, Dockerfile, конфигов).
- `docs/OPERATIONS.md`: локальный запуск, backup/restore PostgreSQL и storage.

Проверки: `ruff`, `mypy`, `pytest` (unit: конфиг, формат ошибок, редактирование логов, health), `alembic upgrade head` на чистой БД (если Docker доступен), `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `docker compose build`/`up` + проверка health (если Docker доступен).

## Этап 03 — Авторизация, роли, bootstrap, аудит

Результат: Argon2id, сессии в БД, login/logout/me/change-password, отзыв сессий, rate limit, CSRF; политики RBAC и scoped-репозитории; bootstrap CLI (идемпотентный, advisory lock, `must_change_password`); API и UI управления пользователями (создание, блокировка, роли, сброс пароля с выдачей одноразового временного пароля и обязательной сменой, ограничения моделей, отзыв сессий); `AuditLog`.

Тесты: хеширование, вход/неудачи/блокировка, CSRF без токена, отзыв сессий, смена пароля инвалидирует сессии, bootstrap (пусто без параметров / создание / повтор не меняет пароль и роль / параллельный запуск), матрица ролей, Admin не может назначить superadmin, последний superadmin, IDOR-заготовки, отсутствие пароля в логах.

## Этап 04 — Загрузка и извлечение

Результат: потоковая загрузка с лимитами, определение формата по сигнатуре, хранилище, задача извлечения в дочернем процессе с лимитами, экстракторы PDF/DOCX, DOC через converter, ZIP-проверки, страницы (§8.4), фрагменты, `clause_ref` только при достоверности, `unsupported_no_text`; авторизованная выдача оригинала; API текста по страницам/фрагментам; выдача доступа к документу; удаление (purge-задача — с явным подтверждением в UI); UI: drag-and-drop, прогресс, статусы, просмотр текста.

Тесты: валидные DOCX (абзацы + таблицы в порядке), PDF со страницами, пустой файл, повреждённые файлы, подмена MIME/расширения, превышение размера, zip-бомба, DOCM, зашифрованный PDF, PDF без текста, превышение страниц, IDOR на документ/файл/фрагменты, DOC (если доступен converter).

## Этап 05 — Провайдеры и каталог моделей

Результат: `LLMProvider`, адаптеры OpenRouter и Ollama (сверка с актуальной документацией API), mock-провайдер, SSRF-guard с pinned IP, шифрование секретов (MultiFernet), API/UI провайдеров и моделей, проверка соединения, импорт списка моделей, разрешения по ролям/пользователям, `/models/available`, глобальный выключатель облака, `ConfigRevision`, snapshot-функция.

Тесты (respx): timeout, 429 с Retry-After, 401, недоступная модель, невалидный JSON, ограниченные повторы, redaction ключа в логах/ошибках/ответах API, SSRF (loopback, private, link-local, metadata, IPv6, редирект, rebinding, userinfo, нестандартная схема), `allow_private_network`, отключённая модель/провайдер, запрещённая пользователю модель. Live-проверки — только при наличии ключа/Ollama, иначе явно «не проводилась».

## Этап 06 — Анализ и доказательства

Результат: версионированные промпты и схемы; создание анализа с проверками (права, модель, облако + согласие, лимиты, идемпотентность); чанкинг с перекрытием; структура; анализ чанков; межраздельный проход; дедупликация; точное сопоставление цитат; верификатор смысловой связи; повтор для неподтверждённых; итоговые статусы; покрытие; сводка; cancel/retry/recovery; детектор prompt injection.

Тесты (mock-провайдер): exact quote, normalized quote, missing quote, wrong page (игнорируется), fake fragment ID, фрагмент другой версии, слишком короткая цитата, нерелевантная цитата, contradiction, missing_clause без цитаты, длинный документ (много чанков, перекрытие, стабильные ключи), дубликаты, unknown party, prompt injection в тексте, невалидный JSON + repair, ошибка провайдера, cancel, retry без пересчёта готовых чанков, recovery после истечения lease, idempotency.

## Этап 07 — UI и отчёты

Результат: все экраны из ARCHITECTURE §16 на реальных API; форма анализа с облачным согласием; прогресс (polling, при возможности SSE); отчёт с фильтрами (уровень, категория, сторона, статус проверки), карточки рисков с тремя различимыми состояниями доказательств и отдельным видом для отсутствующих условий; экспорт PDF/DOCX/CSV/XLSX; админка без раскрытия секретов; журнал аудита.

## Этап 09 — Финальная приёмка

Проход по `ACCEPTANCE_CHECKLIST.md` с фактической проверкой каждого пункта, исправления без риска потери данных, итоговый отчёт с реальными результатами и перечнем непроверенного.

## Решения, принятые на этапе 01 (могут быть пересмотрены по запросу)

1. Очередь задач в PostgreSQL, без Redis.
2. Admin не читает чужие договоры без явного доступа; Superadmin — может, с аудитом.
3. Страницы DOCX/DOC — по сохранённой разметке Word, иначе по рендеру LibreOffice, с пометкой источника; если не удаётся — не указываются.
4. Смысловая проверка цитат — отдельный вызов модели-верификатора; по умолчанию та же модель, что и анализ (для облачной модели это дополнительная передача уже отправленных фрагментов тому же провайдеру — входит в то же согласие).
5. Название документа не пишется в аудит.
6. PDF-экспорт через reportlab (без HTML-рендера), чтобы исключить HTML-injection и тяжёлые системные зависимости.
7. Python 3.13 в образах (совпадает с машиной разработки).
