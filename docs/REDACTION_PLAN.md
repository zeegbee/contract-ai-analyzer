# Дополнительный этап 10 — Маскировка конфиденциальных и персональных данных перед облачным анализом

Статус: **реализовано 2026-10-21** (результаты и отклонения от плана — раздел «Этап 10» в `docs/IMPLEMENTATION_STATUS.md`; составлен 2026-10-20 по запросу владельца продукта). Этап не входит в промпты 00–09; выполняется по отдельной команде владельца. Правила проекта (`00-master-and-workflow.md`, CLAUDE.md) действуют полностью: без демо-данных, дословные цитаты с реальным fragment ID и страницей, текст договора — недоверенные данные, секреты только в env, без разрушительных миграций, в конце этапа — реальные проверки и раздел в `docs/IMPLEMENTATION_STATUS.md`.

## 1. Решения владельца (2026-10-20)

1. **Категории маскировки** настраивает Superadmin; предусмотреть все практически значимые категории (§3), каждую можно включить или выключить.
2. **Экран предпросмотра обязателен**: облачный анализ нельзя запустить, не открыв и не подтвердив предпросмотр маскировки (§6).
3. **Маскировка только для облачных моделей.** Для локальных моделей (Ollama) маскировка и предпросмотр не применяются: текст не покидает инфраструктуру (уточнение владельца 2026-10-20).

Решения «по умолчанию» (можно пересмотреть):
- Это псевдонимизация (замена на метки с обратной подстановкой), а не шифрование текста: модель не может анализировать зашифрованный текст. Шифруется таблица соответствий.
- Можно ли пользователю отправить текст в облако без маскировки, решает Superadmin настройкой `allow_unmasked` (по умолчанию выключена — маскировка для облака обязательна). Решение владельца (2026-10-20): настройка остаётся; **включение — только после предупреждения и подтверждения** Superadmin; **отправка без маскировки — только после отдельного предупреждения и подтверждения** пользователя (в дополнение к существующему облачному согласию). При выключенной настройке кнопки «Отправить без маскировки» нет. При обычной отправке с маскировкой отдельного окна нет — остаётся существующее облачное предупреждение (подтверждено владельцем).
- По умолчанию включены персональные данные и реквизиты; коммерческие категории (суммы, ставки, даты, номера договоров) выключены — их маскировка ухудшает анализ (неустойки, сроки, соразмерность).
- В интерфейсе и документации нельзя утверждать, что «все персональные данные удалены»: распознавание неполное. Формулировка: «снижает объём передаваемых данных; проверьте подсвеченное».
- Псевдонимизированные данные по 152-ФЗ остаются персональными; решение о трансграничной передаче — за владельцем/юристом (фиксируется в SECURITY_AND_PRIVACY).

## 2. Как работает (кратко)

```
версия документа (фрагменты, канонический текст)
  → обнаружение (локально, в worker/песочнице): правила + NER + словари
  → предпросмотр: пользователь снимает/добавляет пометки, подтверждает
  → при запуске анализа: замороженная таблица «метка → вхождения» (зашифрована)
  → конвейер: в промпты идут замаскированные фрагменты (structure, chunks, cross_section, quote_retry, verifier)
  → ответы модели: цитаты сопоставляются с замаскированным текстом → смещения переводятся в исходный текст
     → проверка точного совпадения (шаг A) по исходному тексту; свободный текст — обратная подстановка меток
  → отчёт и экспорт — с исходными значениями
```

## 3. Категории

Метки вида `⟦ЛИЦО_1⟧` (символы `⟦⟧` редки в договорах; если они встречаются в тексте — экранируются заменой на похожие символы до маскировки, чтобы метку нельзя было подделать текстом договора).

**Пользовательские правила (Superadmin)**
- `custom_dictionary` — список слов и фраз (наименования контрагентов, проектов, торговые марки) с категорией и меткой; поиск с учётом морфологии.
- `custom_pattern` — регулярные выражения. Защита от ReDoS: движок `google-re2` (линейное время) или ограниченный синтаксис; проверка шаблона при сохранении, лимит длины и количества.
- `allow_list` — слова, которые никогда не маскируются (например, «Заказчик», «Исполнитель», наименование своей организации — по решению Superadmin).

## 4. Обнаружение: реализация

- Модуль `backend/app/redaction/`: `categories.py` (реестр категорий, метаданные для UI), `detectors/` (`patterns.py` — шаблоны и контрольные суммы, `ner.py` — NER, `dictionary.py`, `context.py`), `linking.py` (связывание вхождений в одну сущность: «Иванов Иван Иванович» / «Иванов И.И.» / «И.И. Иванову»; полное и краткое наименование организации), `propagate.py` (найденные формы ищутся по всему тексту — если NER пропустил вхождение в одном месте), `mask.py` (построение замаскированного текста и карты смещений), `unmask.py` (обратный перевод), `settings.py` (схема настроек), `__init__.py` (`REDACTION_VERSION`).
- NER для русского: **проверить в начале этапа** совместимость с Python 3.13 и лицензии: Natasha (`natasha`/`slovnet`/`navec`, MIT) + `pymorphy3` (MIT) + `razdel`; запасной вариант — spaCy `ru_core_news_sm/md` (MIT). Модели — в образе (без загрузки из сети при работе), версии закрепить, `requirements.lock` перегенерировать, `docs/LICENSES.md` дополнить. Оценить прирост размера образа.
- Обнаружение выполняется в worker'е задачей `redaction_scan` (длинные документы, CPU), с лимитами по времени/памяти по образцу `ingestion/sandbox.py`. Результат — список сущностей: категория, `fragment_id`, смещения в тексте фрагмента, нормализованное значение (для связывания), источник (`pattern|ner|dictionary|propagated|manual`), уверенность. Значения в логах не пишутся — только счётчики.
- Детерминированность: при одинаковом тексте, настройках и `REDACTION_VERSION` — одинаковый результат (для тестов и повторов).

## 5. Модель данных (миграция 0008, только добавление)

- `system_settings.redaction` — `{"categories": {code: {"enabled": bool}}, "allow_unmasked": bool, "custom_dictionary": [...], "custom_patterns": [...], "allow_list": [...], "preview_ttl_hours": 24}`; изменения — `config_revisions` + аудит `settings.updated` (по образцу retention). Включение `allow_unmasked` требует `confirm_allow_unmasked: true` в запросе, иначе 409 `redaction_unmasked_confirmation_required` (как `retention_confirmation_required`); выключение — без подтверждения; отдельный аудит `redaction.unmasked_allowed` / `redaction.unmasked_disallowed`. Ревизия настроек используется для инвалидации предпросмотров.
- `redaction_previews`: `id`, `version_id` (FK, `ON DELETE CASCADE`), `created_by_id`, `settings_revision`, `redaction_version`, `status` (`scanning|ready|failed|confirmed|expired`), `entities_encrypted` (BYTEA, SecretBox: найденные сущности + правки пользователя), `counts` (JSONB: категория → число, без значений), `error_code`, `created_at`, `confirmed_at`, `expires_at`.
- `analysis_redactions`: `analysis_id` (PK, FK `ON DELETE CASCADE`), `preview_id`, `mode` (`masked|unmasked_by_user`), `unmasked_confirmed_at`, `mapping_encrypted` (BYTEA: метки → вхождения с исходными смещениями), `counts`, `redaction_version`, `settings_revision`.
- Удаление документа (`purge_document`) удаляет и эти строки; housekeeping удаляет просроченные неподтверждённые предпросмотры (временные данные; согласовать с владельцем вместе с этапом).
- `app.cli rotate-secrets` перешифровывает `entities_encrypted` и `mapping_encrypted`.

## 6. API и права

- `GET /api/admin/redaction` — Admin и Superadmin (чтение); `PUT /api/admin/redaction` — только Superadmin (`policies.can_manage_redaction`), проверка шаблонов (re2), `extra="forbid"`.
- `POST /api/documents/{id}/versions/{vid}/redaction-previews` — создать предпросмотр (право анализа документа через `scoped.get_version_for`); ставит задачу `redaction_scan`.
- `GET /api/redaction-previews/{id}` — статус, сущности для подсветки (значения отдаются только автору предпросмотра с правом на документ), счётчики. Чужой → 404 (`scoped.get_redaction_preview_for`).
- `PATCH /api/redaction-previews/{id}` — правки: снять пометку с сущности целиком или с отдельного вхождения, сменить категорию, добавить ручную пометку (фрагмент + смещения; сервер проверяет границы), «искать и пометить все вхождения».
- `POST /api/redaction-previews/{id}/confirm` — фиксирует состояние; поле `mode: masked|unmasked`; `unmasked` — только при `allow_unmasked` (иначе 403 `redaction_unmasked_not_allowed`) и с обязательным `confirm_unmasked: true` + `unmasked_notice_version` (версия текста предупреждения, как у облачного согласия; без них — 422 `redaction_unmasked_confirmation_required`). Время подтверждения сохраняется в `analysis_redactions.unmasked_confirmed_at`, аудит `redaction.sent_unmasked`.
- `POST /api/analyses` (только облачная модель): обязателен `redaction_preview_id` в статусе `confirmed` — того же пользователя, той же версии, не просрочен, ревизия настроек не менялась; иначе 422 `redaction_preview_required` / 409 `redaction_settings_changed`. Предпросмотр расходуется (одна связка с анализом). `estimate` не требует предпросмотра.
- `retry` анализа использует ту же таблицу соответствий (не пересканирует).
- Аудит: `redaction.settings_updated`, `redaction.preview_confirmed` (счётчики по категориям, число ручных добавлений/снятий, режим), `analysis.started` (`redaction: masked|unmasked_by_user|not_applicable`). Значения — никогда.
- Новые маршруты — в `test_security_sweep.py` (`SELF_ROUTES` для маршрутов без ID объекта).

## 7. Встраивание в конвейер анализа (`backend/app/analysis/runner.py`)

- `_prepare`: при наличии `analysis_redactions` (`mode=masked`) строится замаскированное представление фрагментов (`FragmentRef.text` для промптов) и карта смещений masked → original по каждому фрагменту. `FragmentIndex` для проверки остаётся на исходном тексте.
- Все вызовы модели (structure, chunks, cross_section, quote_retry, verifier шага B) получают только замаскированный текст. Проверка prompt injection (`_scan_injection`) — по исходному тексту, как сейчас.
- Промпты: инструкция сохранять метки `⟦…⟧` дословно и не пытаться восстанавливать скрытые значения; повысить версии в `PROMPT_VERSIONS`. Метки обнаруживаются также в заголовках разделов (`structure`).
- Цитаты: цитата модели ищется в **замаскированном** тексте указанного фрагмента (той же нормализацией `quotes.py`), найденный диапазон переводится картой смещений в исходный текст → в `RiskEvidence` сохраняется исходная цитата, проверка шага A — по исходному тексту. Метка, искажённая моделью (склонение, перевод, другой номер) → совпадения нет → существующий `quote_retry`; неизвестная метка в цитате → `not_found`.
- Свободный текст (заголовок риска, описание, рекомендации, резюме, cross_section): метки заменяются на каноническую форму сущности (первое полное вхождение, именительный падеж через pymorphy3, если доступен). Нераспознанные/выдуманные метки оставляются как есть и помечаются.
- В snapshot анализа: `redaction: {mode, redaction_version, settings_revision, counts}` — для воспроизводимости; `PIPELINE_VERSION` повысить.
- Оценка токенов: метки короче или длиннее значений — оценка считается по замаскированному тексту.

## 8. Frontend

- **Настройки → «Маскировка данных»** (`frontend/src/pages/admin/RedactionSection.tsx`): категории по группам с переключателями, надёжность метода, предупреждения для коммерческих категорий; `allow_unmasked` — при включении модальное окно с предупреждением (персональные и конфиденциальные данные будут уходить внешнему провайдеру без маскировки, ответственность, 152-ФЗ) и подтверждением отметкой + кнопкой «Разрешить»; без подтверждения запрос не отправляется; словарь, шаблоны (с проверкой на сервере), список исключений; срок жизни предпросмотра. Admin — только чтение, Superadmin — изменение.
- **Новый анализ** (`NewAnalysisPage.tsx`): при облачной модели кнопка запуска заменяется шагом «Проверить маскировку» → страница предпросмотра:
  - текст документа по фрагментам (виртуализированный список для длинных документов), подсветка по категориям, легенда и фильтр категорий;
  - боковая панель: сущности, сгруппированные по значению (значение, категория, число вхождений, источник, надёжность), переключатели «маскировать»; элементы с низкой уверенностью — в отдельном блоке «Проверьте»;
  - ручная пометка выделением текста + выбор категории; «пометить все вхождения»;
  - переключатель «Как увидит модель» (текст с метками);
  - сводка счётчиков; обязательная отметка «Подсвеченные данные проверены»; кнопки «Подтвердить и запустить анализ» и — только при `allow_unmasked` — «Отправить без маскировки» → модальное окно с предупреждением (сколько значений по каким категориям уйдёт в облако открытым текстом, провайдер, модель) и обязательной отметкой «Понимаю, что данные будут переданы без маскировки» → кнопка «Отправить без маскировки»; отмена возвращает к предпросмотру;
  - состояния: сканирование (polling), ошибка, предпросмотр устарел (настройки изменились или истёк срок) → «Проверить заново».
- **Отчёт**: в шапке — «При анализе скрыто N значений (категории…)» или «Отправлено без маскировки»; экспорт содержит ту же строку.
- Тексты — `src/i18n/ru.ts`, схемы — zod в `src/api/redaction.ts`, тесты Vitest/MSW.

## 9. Проверки этапа

Backend (unit):
- контрольные суммы и шаблоны каждой категории: положительные и отрицательные примеры (ИНН 10/12, ОГРН/ОГРНИП, СНИЛС, ключ счёта с БИК, Луна, IBAN, VIN);
- связывание и склонения ФИО и организаций; распространение форм; allow_list; словарь с морфологией; ReDoS-шаблон отклоняется;
- маскировка/обратный перевод: карта смещений на краях фрагментов, соседние и вложенные сущности, экранирование `⟦⟧` из текста договора;
- детерминированность.

Backend (integration, `api`):
- облачный анализ без предпросмотра → 422; чужой предпросмотр → 404; предпросмотр другой версии → 422; изменение настроек → 409; Analyst/Viewer без права анализа → 403/404;
- **запросы к mock-провайдеру (`Recorder`) не содержат ни одного замаскированного значения**; содержат метки;
- цитаты в рисках — исходный текст, шаг A проходит, страница и fragment ID реальные; искажённая метка → `quote_retry`; повтор анализа использует ту же таблицу;
- в БД нет открытых значений: `entities_encrypted`/`mapping_encrypted` не содержат исходных строк; `counts` и аудит — без значений; логи (`caplog`) — без значений;
- включение `allow_unmasked` без `confirm_allow_unmasked` → 409, с ним — включено + аудит; Admin → 403; `unmasked` при выключенной `allow_unmasked` → 403; при включённой без `confirm_unmasked` → 422, с ним — аудит, `unmasked_confirmed_at` и отметка в отчёте; локальная модель — предпросмотр не требуется и не создаётся, в промпты идёт исходный текст;
- удаление документа удаляет предпросмотры и таблицы; `rotate-secrets` перешифровывает;
- PUT настроек — только Superadmin; security sweep с новыми маршрутами; миграция — `alembic check`, тест на отсутствие разрушительного SQL.

Качество обнаружения:
- размеченный набор синтетических договоров (на основе `samples/` + генерация в `tests/docfactory.py`): точность/полнота по каждой категории записываются в IMPLEMENTATION_STATUS фактическими числами, без округления в лучшую сторону.

Frontend: настройки (роль), предпросмотр (подсветка, снятие/добавление, «как увидит модель», устаревший предпросмотр, отправка без маскировки: без отметки кнопка неактивна, отмена не отправляет запрос), окно подтверждения при включении `allow_unmasked`, отметка в отчёте.

E2E: сценарий Playwright с предпросмотром. Проверить, можно ли на стенде `cai-e2e` пометить mock-провайдер как облачный (netguard разрешает публичные адреса только для облачных — mock в частной подсети); если нельзя — тестовый режим только для e2e не вводить, проверить через integration-тесты и отметить в отчёте.
