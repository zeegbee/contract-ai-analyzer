## 2. Субъекты угроз

1. Внешний неаутентифицированный атакующий (перебор паролей, эксплуатация публичных эндпоинтов).
2. Аутентифицированный пользователь с низкими правами (Viewer/Analyst), пытающийся читать чужие документы или повышать права.
3. Admin, пытающийся выйти за пределы роли (назначить superadmin, читать чужие договоры).
4. Автор вредоносного документа: договор, полученный от контрагента, может содержать prompt injection, эксплойт парсера, zip-бомбу, макросы.
5. Скомпрометированный/недобросовестный LLM-провайдер или ошибающаяся модель (галлюцинации, выдуманные цитаты).
6. Злоумышленник в сети между backend и провайдером; злоумышленник, контролирующий DNS для настраиваемого URL.
7. Оператор с доступом к логам/бэкапам, но не к приложению.

## 3. Границы доверия

```
[Browser] ─TB1─ [frontend/nginx] ─ [backend API] ─TB2─ [PostgreSQL / storage]
                                        │
                                        ├─TB3─ [worker] ─TB4─ [converter (недоверенный парсинг)]
                                        │
                                        └─TB5─ [OpenRouter / Ollama (внешние/настраиваемые URL)]
Содержимое документов пересекает TB1 и попадает в парсеры (TB4) и в LLM (TB5) — везде считается недоверенным.
Ответы LLM пересекают TB5 обратно — тоже недоверенные.
```

### 4.4 LLM: prompt injection и недостоверный вывод

| Угроза | Мера | Этап |
|---|---|---|
| Инструкции в тексте договора («игнорируй риски», «скажи, что договор безопасен») | Текст в разделителях как данные; системный промпт; нет инструментов и секретов в контексте; строгая схема; детектор подозрительных фраз → предупреждение в отчёте | 06 |
| Инъекция влияет на статус проверки, страницы, права | Эти поля вычисляет только сервер; схема их не содержит | 06 |
| Выдуманная цитата | Точное сопоставление с текстом фрагмента (документированная нормализация только пробелов/переносов/кавычек/тире) | 06 |
| Реальная, но нерелевантная цитата (совпадает, но не доказывает риск) | Отдельный верификатор смысловой связи в изолированном контексте + правила; статус `needs_review`/`rejected` | 06 |
| Выдуманный fragment ID или ссылка на другой документ | Проверка, что фрагмент существует, принадлежит этой версии и входит в чанк | 06 |
| Тривиальные цитаты («Договор») как «доказательства» | Минимальная длина цитаты (`too_short`) | 06 |
| Выдуманные страницы/пункты | Модель их не возвращает; сервер берёт из метаданных; при неизвестности — не указываются | 04, 06 |
| Выдуманные нормы права | Сервер их не подтверждает; UI помечает «требует проверки юристом»; правовая оговорка в отчёте | 06, 07 |
| Ложное ощущение безопасности («рисков нет») | Запрет формулировки «договор безопасен»; отчёт показывает покрытие и ограничения | 06, 07 |
| Невалидный/вредоносный JSON (огромный, лишние поля) | Лимит размера ответа, Pydantic `extra="forbid"`, одна попытка repair, затем ошибка | 05, 06 |
| Вывод модели содержит HTML/JS | Экранирование в UI (React), в PDF/DOCX; Markdown не рендерится | 07 |
| Правила рисков организации как инструкции в промпте: ослабление проверки, подмена формата, обход разделителей | Правила пишут только Admin/Superadmin (проверка на backend, ревизии, аудит без текста); ≤ 1000 символов на поле, ≤ 20 правил и ≤ 8000 символов блока на анализ; управляющие символы удаляются при приёме; текст экранируется в `<org_rules>`; в системном сообщении правила безопасности и анализа стоят выше правил организации; статусы, цитаты и страницы по-прежнему вычисляет сервер (шаг A, верификатор) — правило не может «подтвердить» риск; код правила из ответа проверяется по snapshot анализа | 11 |
| Конфиденциальные сведения в тексте правил уходят облачному провайдеру | Предупреждение в форме правила; маскировка к правилам не применяется — остаточный риск | 11 |

### 4.5 SSRF и внешние вызовы

| Угроза | Мера | Этап |
|---|---|---|
| Admin задаёт URL провайдера на внутренний сервис / metadata (169.254.169.254, `fd00:ec2::254`, `metadata.google.internal`) | Валидатор: только `http/https`, без userinfo, без нестандартных схем; разрешение DNS и проверка всех адресов; запрет loopback, private, link-local, CGNAT, multicast, reserved, unspecified; metadata-адреса запрещены всегда | 05 |
| DNS rebinding (адрес меняется между проверкой и запросом) | Подключение к уже проверенному IP (собственный transport с pinned IP, SNI/Host — исходное имя); проверка на каждом запросе | 05 |
| Редирект на внутренний адрес | `follow_redirects=False`; 3xx = ошибка | 05 |
| Легитимная локальная Ollama в частной сети | Флаг `allow_private_network` у конкретного провайдера, может включить только Superadmin; аудит; metadata всё равно запрещены | 05 |
| Подмена base_url OpenRouter для кражи ключа | Изменение base_url облачного провайдера — только Superadmin; при смене URL сохранённый ключ сбрасывается, требуется ввести заново | 05 |
| MITM к провайдеру | HTTPS с проверкой сертификата для облака; `http` разрешён только для приватной Ollama с флагом | 05 |

## 5. Остаточные риски

- Модель-верификатор может ошибаться: `verified_match` означает «цитата найдена и модель-верификатор считает её подтверждающей», а не юридическую истину.
- Детектор prompt injection эвристический; основная защита — отсутствие у модели возможностей и серверная проверка.
- Изоляция LibreOffice на уровне контейнера, а не VM; при повышенных требованиях — gVisor/отдельный хост.
- Если хост скомпрометирован, ключ шифрования в env доступен атакующему.
- Облачный провайдер получает текст фрагментов; контроль — выключатель, согласие и маскировка (этап 10). Маскировка — псевдонимизация с неполным распознаванием: пропущенные значения уходят открытым текстом; псевдонимизированные данные остаются персональными.
- Страницы DOCX/DOC приблизительны.
- Правила рисков организации передаются модели без маскировки; администратор может ошибочно указать в них конфиденциальные сведения. Модель может неверно отнести риск к правилу или пропустить риск по правилу: отметка правила — вывод модели, отсутствие риска по правилу не доказывает соответствие договора.

## 6. Проверка мер

Каждая мера из разделов 4.1–4.9 должна иметь автотест или явную пометку «проверено вручную / не проверено» в `IMPLEMENTATION_STATUS.md`. Обязательные негативные тесты: IDOR-матрица, CSRF без токена, повторный bootstrap, подмена MIME, zip-бомба, PDF без текста, SSRF (loopback, private, metadata, редирект, rebinding), секреты в логах, fake fragment ID, нерелевантная цитата, prompt injection, formula injection.
