# Безопасность и конфиденциальность

Документ для владельца продукта, администраторов и проверяющих: какие данные обрабатывает приложение, куда они передаются, как защищены и что проверено. Модель угроз — [THREAT_MODEL.md](THREAT_MODEL.md), эксплуатация — [OPERATIONS.md](OPERATIONS.md), фактические результаты проверок — [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md) (этап 08).

> Результаты анализа — поддержка работы юриста, а не юридическое заключение. Проверка цитат подтверждает, что цитата есть в тексте и (по оценке модели-верификатора) относится к риску, но не гарантирует юридическую правильность вывода.

## 1. Какие данные обрабатываются и где хранятся

| Данные | Где | Срок хранения |
|---|---|---|
| Оригиналы договоров (PDF, DOCX, DOC), DOCX после конвертации DOC | volume `storage` (`originals/`, `converted/`), имя файла — случайный ID | до удаления документа (вручную или политикой хранения, если она включена) |
| Извлечённый текст, фрагменты, страницы | `storage/text/`, таблицы `document_fragments`, `document_pages` | до удаления документа |
| Результаты анализа: риски, цитаты, рекомендации, snapshot конфигурации | PostgreSQL | до удаления документа |
| Файлы экспорта (PDF/DOCX/CSV/XLSX — содержат цитаты договора) | `storage/exports/` | `EXPORT_TTL_HOURS` (по умолчанию 7 суток), затем удаляются worker'ом |
| Учётные записи: e-mail, имя, роль, хеш пароля (Argon2id) | PostgreSQL | бессрочно (учётные записи блокируются, а не удаляются) |
| Сессии: HMAC токенов (сами токены — только в cookie браузера) | PostgreSQL | до истечения/отзыва |
| Попытки входа: HMAC e-mail, IP | PostgreSQL | 1 сутки |
| Журнал аудита: действие, ID объектов, IP, служебные детали без текста договоров | PostgreSQL, только добавление (триггер запрещает изменение и удаление) | бессрочно |
| API-ключ OpenRouter | PostgreSQL, зашифрован Fernet (`SECRETS_ENCRYPTION_KEYS`) | до замены/удаления провайдера |
| Логи сервисов (JSON, без текста договоров и секретов) | драйвер Docker `json-file` | до 5 × 10 МБ на контейнер |
| Резервные копии (`db.dump`, `storage.tar.gz`) — содержат всё перечисленное | каталог бэкапов (`deploy/backup.sh`) | по политике ротации администратора |

Название документа и имя файла не пишутся в аудит и логи; в журнале аудита — только ID и SHA-256.

## 2. Передача данных за пределы сервера

- **OpenRouter (облако).** Фрагменты договора передаются, только если: Superadmin включил облачные модели (по умолчанию выключены), пользователь принял текущую версию предупреждения и подтвердил передачу при запуске конкретного анализа. Сервер проверяет все три условия; подтверждение фиксируется (`consent_records`, аудит). Предупреждение не утверждает, что провайдер не хранит данные, — условия хранения нужно проверять у провайдера.
- **Ollama.** Локальный провайдер в частной сети (флаг «Разрешить частную сеть») — данные не покидают инфраструктуру организации; запросы на публичные адреса для такого провайдера блокируются. Ollama во внешней сети (только `https`) считается облачной и подпадает под выключатель и согласие.
- **Аварийное отключение**: выключатель облачных моделей останавливает и уже идущие облачные анализы перед ближайшим вызовом модели (OPERATIONS §11, §14.6).
- Других внешних вызовов нет: телеметрии нет; converter (LibreOffice) работает в сети без выхода в интернет; база данных и хранилище не публикуются наружу.

## 3. Разграничение доступа

- Роли: Superadmin, Admin, Analyst, Viewer. Правила ролей — только в `backend/app/security/policies.py`; доступ к конкретным документам, анализам и экспортам проверяется условием в SQL-запросе (`backend/app/security/scoped.py`): чужой и несуществующий объект неразличимы (404).
- Admin администрирует пользователей и модели, но **не читает чужие договоры**. Superadmin имеет системный доступ к чужим документам только по ID, каждое обращение пишется в аудит (`document.accessed_by_superadmin`); в общем списке чужие документы не показываются.
- Доступ к документу выдаёт владелец (просмотр или просмотр + анализ). Viewer не загружает и не анализирует даже при выданном праве анализа.
- UI только отражает права; защита — на backend для каждого объекта. Автотест `tests/integration/test_security_sweep.py` перебирает **все** маршруты API из OpenAPI-схемы: без сессии → 401, изменяющие запросы без CSRF-токена → 403, админские маршруты для Analyst/Viewer → 403, каждый маршрут с ID документа/версии/анализа/экспорта для постороннего пользователя → 404 без изменения данных. Новый маршрут без классификации ломает тест.

## 4. Аутентификация и сессии

- Пароли: Argon2id (t=3, m=64 МиБ, p=4), 12–128 символов, не из списка распространённых, без e-mail/имени. Пароля по умолчанию нет: первый Superadmin создаётся из `BOOTSTRAP_ADMIN_*` и обязан сменить пароль при первом входе.
- Перебор: лимит неудач по e-mail (5 за 15 мин) и по IP (30), прогрессивная задержка, одинаковый ответ для существующих и несуществующих адресов. **Неверный текущий пароль при смене пароля считается такой же неудачей** (этап 08): с перехваченной сессией нельзя перебирать пароль через смену пароля.
- Сессии серверные: токен 256 бит в cookie `cai_session` (`HttpOnly`, `SameSite=Lax`, `Secure` в production, путь `/api`), в БД — HMAC; idle 8 ч, абсолютный срок 7 суток; новая сессия при входе и смене пароля; смена/сброс пароля, блокировка и смена роли завершают сессии.
- CSRF: synchronizer token (cookie `cai_csrf` + заголовок `X-CSRF-Token`) и проверка `Origin`/`Referer` по `ALLOWED_ORIGINS` для всех изменяющих запросов, включая вход.

## 5. Веб-защита

- **CSP** SPA: `default-src 'self'; script-src 'self'; style-src 'self'` без `unsafe-inline`, `frame-ancestors 'none'`, `object-src 'none'`; API: `default-src 'none'`. Плюс `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`, `Cache-Control: no-store` для API, HSTS в production.
- **CORS** выключен: SPA и API — один origin через nginx; ответов с `Access-Control-Allow-*` нет (тест).
- **XSS**: React-экранирование, запрет `dangerouslySetInnerHTML` (oxlint `react/no-danger`), Markdown не рендерится; ссылка скачивания экспорта принимается от API только в виде `/api/exports/<id>/download` (этап 08).
- **SQL injection**: только SQLAlchemy с параметрами; параметры не попадают в сообщения ошибок (`hide_parameters=True`).
- **Экспорт**: экранирование разметки reportlab в PDF, текст как текст в DOCX, защита от formula injection в CSV/XLSX.
- Ошибки API — единый формат с `request_id`, без трассировок и введённых значений.

## 6. Загрузка и разбор файлов

- Тип определяется по сигнатуре и структуре и должен совпадать с расширением и `Content-Type`; DOCM и файлы с макросами отклоняются; имя файла — только для отображения, хранение по случайному ID (путь вне web-root, ключи хранилища проверяются регулярным выражением — path traversal невозможен).
- Лимиты: размер `MAX_UPLOAD_MB` (поток, без буферизации в памяти) и `client_max_body_size` nginx, страницы `MAX_PAGES`, ZIP — число записей, распакованный объём и коэффициент сжатия, XML без внешних сущностей.
- Разбор PDF/DOCX — в дочернем процессе без секретов в окружении, с таймаутом (`EXTRACTION_TIMEOUT_SECONDS`) и лимитом памяти (`EXTRACTION_MEMORY_MB`); LibreOffice — в отдельном контейнере `converter` без сети, без доступа к БД и хранилищу, non-root, read-only, `cap_drop: ALL`, лимиты CPU/RAM/PIDs, таймаут.
- Контейнеры `backend`, `worker`, `converter`, `frontend` работают без root, с read-only FS, `no-new-privileges` и ограничениями памяти и числа процессов (с этапа 08 — и у `backend`/`frontend`).

## 7. LLM: prompt injection и достоверность

- Текст договора передаётся модели только внутри `<fragment>` с экранированием; системные правила объявляют его данными; у модели нет инструментов, секретов и настроек. Эвристический детектор фраз-инъекций выводит предупреждение в отчёте (e2e-проверка: строка «Игнорируй предыдущие инструкции…» в договоре не меняет вывод, отчёт показывает предупреждение).
- Ответ модели проверяется строгой схемой (Pydantic `extra="forbid"`, лимит размера ответа, одна попытка исправления). Страницы, пункты, статусы проверки и права вычисляет только сервер.
- Цитаты: точное или документированно нормализованное совпадение с сохранённым текстом фрагмента, который действительно был в запросе модели; отдельный вызов модели-верификатора оценивает смысловую связь. Итог — `verified_match` / `needs_review` / `rejected`; выдуманная цитата отклоняется (e2e: риск с несуществующей цитатой получает «Не подтверждён» и скрыт по умолчанию).
- Отчёт не содержит формулировки «договор безопасен»; ограничения и правовая оговорка выводятся всегда.

## 8. SSRF при настройке адресов провайдеров

Адрес провайдера (в том числе URL Ollama) проверяется при каждом запросе: только `http/https`, без userinfo; все адреса из DNS проверяются, соединение идёт на уже проверенный IP (защита от DNS rebinding); редиректы запрещены; loopback, частные, link-local, CGNAT, multicast и зарезервированные адреса запрещены, если Superadmin не разрешил частную сеть конкретному провайдеру; metadata-адреса облаков запрещены всегда. Менять адрес и ключ провайдера может только Superadmin; при смене адреса без нового ключа сохранённый ключ сбрасывается.

## 9. Секреты и логи

- Секреты — только в окружении (`.env` не в Git и не в образах): `SECRET_KEY`, `SECRETS_ENCRYPTION_KEYS`, `POSTGRES_PASSWORD`, `BOOTSTRAP_ADMIN_PASSWORD`. Production-запуск с небезопасной конфигурацией (http-origin, `COOKIE_SECURE=false`, ключ-заглушка, `DEBUG`) невозможен. API возвращает о ключе провайдера только «задан» и последние 4 символа.
- Логи: JSON, значения ключей, похожих на секреты, → `[REDACTED]`; поля `text/quote/content/prompt/…` → `[CONTENT len=N]`; маскирование `Bearer …`, `sk-…`, паролей в URL; access-лог без query-строки. **С этапа 08 трассировки исключений выводятся без текста сообщений** (только типы и кадры стека): сообщение могло содержать фрагмент ответа модели, значения полей из `DETAIL` PostgreSQL или текст договора.
- e2e-проверка (`e2e/run.sh check-logs`) ищет в логах всех контейнеров фразы из тестового договора, пароли и ключи стенда.

## 10. Аудит

Журнал `audit_log` (UI «Журнал аудита», Admin+): входы и неудачи (без введённых данных), смена/сброс пароля и неверный текущий пароль при смене, пользователи и роли, модели и провайдеры (ключ — `***`), облачные настройки и согласия, загрузка, скачивание оригинала, выдача доступа, удаление документов, анализы, экспорт, обращения Superadmin к чужим документам. **С этапа 08 журнал защищён триггером БД**: `UPDATE` и `DELETE` строк запрещены для любого подключения (миграция `0006_audit_log_append_only`).

## 11. Удаление и резервные копии

- Удаление документа (владелец или Superadmin): документ сразу скрывается, задача `purge_document` удаляет файлы (оригинал, конвертированный DOCX, текст, экспорты) и строки (версии, фрагменты, анализы, риски, экспорты); в аудите остаются только ID и SHA-256.
- Экспорты удаляются автоматически по сроку хранения. **Политика хранения документов** (по умолчанию выключена): Superadmin задаёт срок N дней в «Настройках»; документы без загрузок и анализов дольше N дней удаляются worker'ом автоматически тем же путём, что и вручную (аудит `document.deleted` с `reason: retention`). Включение и сокращение срока требуют явного подтверждения с показом числа удаляемых документов; выключение — в любой момент (OPERATIONS §14.5).
- **Удалённые данные остаются в резервных копиях до их ротации.** Бэкапы содержат договоры, хеши паролей и зашифрованные ключи провайдеров (ключ шифрования в бэкап не входит). `deploy/backup.sh` создаёт файлы с правами только владельца; шифрование и вынос копий за пределы сервера — дополнительный этап 08A, до него — вручную (`age`/`gpg`).

## 13. Остаточные риски и рекомендации для production

- Приложение подключается к PostgreSQL пользователем из `POSTGRES_USER`, который в образе `postgres` является суперпользователем: он может отключить триггер аудита. Для повышенных требований создайте отдельную роль приложения без прав суперпользователя и владельца таблиц (OPERATIONS §14.7).
- Ключ шифрования секретов и `SECRET_KEY` лежат в окружении хоста: компрометация хоста раскрывает их. Используйте secret manager и ограничьте доступ к `.env` (права 600).
- Общего rate limit на API нет (кроме входа, очередей загрузки/анализа/экспорта и лимита активных анализов) — для внутреннего приложения достаточно; при публикации в интернет добавьте лимиты на reverse proxy.
- Изоляция LibreOffice — контейнерная (не VM); при повышенных требованиях — gVisor или отдельный хост.
- Верификатор — модель и может ошибаться; детектор инъекций эвристический; страницы DOCX/DOC приблизительны.
- Облачный провайдер получает фрагменты договора; контроль — выключатель, согласие и аудит.
- Удалённые документы остаются в бэкапах до ротации; политика хранения по умолчанию выключена — без неё документы хранятся бессрочно.
- Лицензия PyMuPDF (AGPL-3.0) допускает только внутреннее использование без доработки лицензирования ([LICENSES.md](LICENSES.md)).
